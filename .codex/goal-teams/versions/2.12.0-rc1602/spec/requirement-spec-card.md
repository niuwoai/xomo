# Requirement Specification Card：抓手只表示真实画布平移

## 核心目标

Xomo 的鼠标形状必须表达“下一次输入真正会做什么”。组件库普通状态使用系统箭头；实际对象拖动使用移动语义；只有真实画布平移才使用开手/闭手。

## 用户问题

现有统一解析器先处理变换控制点，后处理 Space 临时平移。用户按住 Space 并悬停在 resize、rotate 或 reference point 上时，可能仍看到变换光标，首击也可能被高优先级控制点手势抢走。另一方面，Move 工具在无可移动内容且不会框选时显示开手，但点击只会 no-op，造成错误动作暗示。

## 主流程

1. 用户在组件或普通图层上看到正常变换控制点。
2. 空闲时按住 Space 或开始中键平移，光标切换为开手；按下拖动后为闭手。
3. 该输入只改变视口偏移，不修改对象 frame 或 History。
4. 若 resize、rotate、reference point 或对象拖动已经开始，后来按 Space 不更换事务。
5. 无可移动目标、无框选能力且不会平移时显示系统箭头。

## 范围边界

- 范围内：光标优先级、首击门控、Space/中键平移、组件和普通图层控制点、空画布 no-op。
- 范围外：工具图标重绘、文档格式、渲染像素、Figma 导入、全量 UI 重构。
- 非目标：将所有对象悬停都改成手形，或让 Space 打断已开始的编辑事务。
