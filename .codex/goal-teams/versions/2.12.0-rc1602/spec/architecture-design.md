# Architecture Design：画布平移优先级

## 设计原则

- 光标和事件捕获使用同一动作优先级，不能“看起来在平移，实际却缩放”。
- 空闲态可以切换动作；已开始事务拥有稳定归属，直至提交或取消。
- 修复位于 UI 输入边界，不改变文档模型或像素渲染。

## 优先级

1. 已开始的对象拖动或变换事务。
2. 已开始的画布平移事务。
3. 空闲态 Space/中键平移意图。
4. 变换控制点悬停与对象移动候选。
5. 当前工具语义。
6. 无动作时系统箭头。

## 接线边界

- `ImageEditorCanvasCursor`：解析同一优先级并修正空白 Move no-op。
- SwiftUI 变换控制点手势：平移意图存在且无活动变换时不启动。
- AppKit 原生捕获：平移意图存在且无活动对象/变换事务时不建立候选。
- 测试：优先使用纯策略与真实事件夹具，源码接线断言只作补充。

## 风险

- 若只改光标不改手势，会产生更危险的视觉/动作不一致。
- 若 Space 无条件优先，会打断活动变换；必须区分空闲意图与活动事务。
- 中键平移与 Space 路径不同，邻接测试必须各自覆盖。
