# Computer Use UI QA

用真实桌面交互形成“观察—操作—再观察—修正—复测”的闭环。把截图、辅助功能树和操作后的状态变化作为证据，不以源码看起来正确代替真实验收。

## 前置要求

1. 完整读取当前环境提供的 `computer-use` Skill，并严格遵循其 `node_repl + @oai/sky` 工作流和确认策略。
2. 使用完整应用路径定位目标，避免同一 bundle identifier 对应多个构建。例如 QPic 调试版使用 `/Applications/QPic Debug.app`。
3. 在操作前列出明确、可观察的验收项。每项必须能由截图、辅助功能树、状态文本或稳定的视觉变化证明。

## 验收循环

### 1. 建立基线

- 调用 `sky.get_app_state({ app, disableDiff: true })`。
- 读取完整辅助功能树，记录窗口、控件标识、选中状态、可操作动作和当前焦点。
- 发出基线截图；截图不足以判断时，不要靠猜测继续。
- 检查：重叠、越界、截断、本地化 key、错误顺序、尺寸不一致、面板内容归属错误、不可见操作入口。

### 2. 执行一个用户动作

- 优先使用最新辅助功能树里的 `element_index`。
- 一次只执行一个动作或一个不可拆分的小批次：点击、滚动一页、拖拽一次、输入一次、按键一次。
- 没有可用辅助功能元素时，才根据最新截图使用坐标。
- 不复用旧状态中的元素索引。

### 3. 立即复查

- 每次动作后再次调用 `get_app_state`，先读状态差异，再决定下一步。
- 在关键状态变化后发出截图，包括展开、选中、显隐、拖拽前后、滚动到底部、缩放前后。
- 对比基线和当前截图，确认目标变化发生且没有产生新的回归。

### 4. 覆盖离屏内容

- 对滚动区域至少检查顶部、一次中间滚动和底部。
- 滚动后重新读取状态并截图，确认标题、内容和操作按钮仍属于正确面板。
- 检查固定栏是否保持可见，内容是否越过自身边界覆盖画布或相邻面板。

### 5. 修正并复测

- 用运行时证据定位到对应 View、ViewModel 或布局约束。
- 修改后运行相关自动化测试并生成干净构建；确认安装的是新版本，不要验证旧进程或旧应用包。
- 用与基线完全相同的动作顺序重跑。
- 只有复测截图和状态共同证明通过时，才报告完成。

## 图层面板专项流程

按顺序验证以下行为：

1. 图层列表始终有明确入口，并显示每个图层的名称、类型或缩略图、选中状态和显隐状态。
2. 点击不同图层行后，主选图层立即切换；辅助功能值和视觉选中态同步更新。
3. 点击眼睛图标后，该图层显隐状态和画布结果立即变化；再次点击可恢复。
4. 从一个图层行拖到另一个图层行前后，列表顺序改变，画布合成顺序同步改变。
5. 拖拽时显示插入位置反馈；放下后选中项不应丢失。
6. 上下滚动长列表，列表工具条、面板标题和画布不应被覆盖。
7. 缩放画布后，左侧工具栏和右侧图层入口仍然可见。

## 证据标准

每项结论至少包含：

- 预期行为；
- 操作前状态或截图；
- 执行动作；
- 操作后状态或截图；
- 是否通过，以及失败时对应的源码位置。

不要把以下内容当作完成证据：

- 仅有编译通过；
- 仅有源码字符串断言；
- 只看到控件存在但没有实际点击；
- 拖拽后没有核对顺序和画布；
- Computer Use 通道失败后仍声称视觉验收通过。

## 故障恢复

- 如果 Node REPL 状态冲突，重用已有变量或重置一次 kernel 后重新初始化 Computer Use。
- 如果原生管道关闭，先用 Finder 等已知稳定应用调用一次 `get_app_state`。稳定应用同样失败时，重置 kernel 并重新初始化；稳定应用成功而目标应用失败时，按目标应用问题继续排查。
- 同一 bundle identifier 有多个历史构建时，使用完整应用路径；若仍失败，检查是否存在多个目标进程，结束无测试数据的旧实例后只启动待验收安装包。不要按 bundle identifier 猜测并验证到错误构建。
- 目标进程存在但读取状态持续断管道时，对原生 App 做 3–5 秒只读 `sample`：主线程持续在事件循环等待表示 App 没有卡死，持续落在布局、状态写入、锁或同步 IO 才按对应调用栈修复。采样不等于 UI 验收证据。
- 检查 `~/Library/Logs/DiagnosticReports/SkyComputerUseService*.ips`。若 Sky 本身以 `EXC_BREAKPOINT` 崩溃，并且故障栈落在 `AccessibilitySupport.UIElementTree.Item.children` 的数组变换，应记录为 Computer Use helper 缺陷；可用仅限 Debug 的 AX 子树二分定位触发范围，并在视觉不变的诊断包中退回最新截图坐标完成可执行项目。最终交付包必须撤掉诊断隔离，不能为了通过工具而永久牺牲产品辅助功能。
- 原子 `drag` 能启动源拖动或显示插入反馈、但始终不能跨行释放时，分别记录“拖动源已启动”和“最终排序未取得视觉证据”。继续验证产品模型测试与接收区实现，但不得把局部反馈写成拖拽排序已通过。
- 排查后只允许再进行一次长超时重试，避免无意义地反复击穿原生通道。
- 如果仍不可用，保留任务为未完成，报告缺少的视觉证据；可以继续做源码和自动化测试，但不得冒充真实桌面验收。
- 遇到确认策略覆盖的高风险操作，在动作发生前按 `computer-use` Skill 要求请求确认。
