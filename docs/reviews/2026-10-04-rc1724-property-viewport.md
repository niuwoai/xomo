# 高级图层属性区不可见诊断

当前 rc1724 App 实机确认 P1 编辑入口缺陷：普通图像的图层面板展开“高级图层设置”后，不透明度、填充和 Blend If 控件没有出现在画面，无法继续本轮滑块历史验收。离屏 SwiftUI 布局对照支持“图层列表抢占空间，属性区被压至零高度”的机制，但生产修复尚未实施或验证。基线 main `398b89f93682fdae68f54d45087050ca3bb0c548`，本轮未修改生产源码、版本或项目编译输入。

## 实机观察与源码路径

现有 rc1724 Release 测试 App 自有 PID 16715 打开仓库 1586×992 的 workbench-backdrop.png，两个像素图层，没有打开用户文档或修改图像。点击“高级图层设置”，AX 明确显示 expanded，并包含不透明度、填充、混合条件的组合文本；截图中只有展开标题，没有滑块。再次收起、展开后，AX 状态再次为 expanded，截图仍没有控件。AX 唯一滑块是画布缩放，没有属性滑块。这是实际界面缺陷，不将单纯缺失 AX 角色等同于渲染失败；截图也没有显示控件。

`veilpic/ImageEditorLayerPanel.swift:283` 将图层列表设为 `layoutPriority(1)`，列表的最小高度是 150，最大高度无限；整个面板在第 301 行固定高度 420。第 336 行的属性 ScrollView 只有 `frame(maxHeight: 112)`，没有保留最小高度。列表优先消耗弹性空间后，最大高度并不能保证属性区域存在。当前该文件 4445 行，修复应结合仓库的 3000 行上限进行相关面板代码分拆，不能借机修改图像算法、属性事务或 Figma 语义。

现有 `ImageEditorLayerPanelStyleTests` 测试原生标签和搜索字段颜色、标题文本接线，但没有验证展开属性区的实际视口尺寸或滑块可操作性；此前属性所有权测试调用模型，不证明界面入口可用。迟到 Binding 值与 Blend If 完成回调的风险仍未物理复现，本轮不能把它们写成已修复或已确认 GUI 故障。
