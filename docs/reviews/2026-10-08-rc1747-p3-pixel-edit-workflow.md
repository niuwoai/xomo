# rc1747 Display P3 像素编辑闭环验证

## 为什么做这条验收

路线图要求优先闭环“打开素材 → 编辑选区像素 → Undo/Redo → 保存重开 → 导出”。此前有 P3 PNG 导入/项目往返、选区移动和 PNG 导出的分项测试，但没有任何单测贯通这几条生产路径。本版增加跨模块验收，避免每个局部都绿、用户走完整任务却出错。

## 覆盖场景

- 测试使用 ImageIO 编码的 8×8 Display P3 PNG，重读确认素材实际带 P3 色彩空间，再经外部图片文档入口载入。
- 对选中图层执行 2×2 矩形选区移动；源像素孔洞变透明，目标位置取得选区的原始导入像素。
- Undo 后项目数据逐字节回到编辑前状态；Redo 后与编辑后项目数据完全相同。
- 以项目数据重开后，复合像素与编辑后完全一致；PNG 再导出为 sRGB profile，尺寸为 8×8，解码像素与重开文档逐字节相同。
- P3→8-bit sRGB 转换与独立浮点计算允许最多 1/255 的量化差异；一旦导入完成，像素移动、保存重开及导出均按导入后的实际像素严格比较。

## 实际结果

- 首轮端到端执行暴露理论浮点换算与 CoreGraphics 8-bit 栅格化相差一个最低有效位（红通道 `[218]` 对 `[217]`）；并非后续编辑链路差异。修正为仅对导入量化容差放宽 1/255，以真实导入样本作精确基准后，最终测试通过。
- 最终新增端到端套件：1/1；像素选区移动：9/9；Quick Export PNG：5/5；P3 PNG 导入/项目往返：1/1。总计 16 项定向测试通过。
- 版本合同 10 runs / 30 assertions，CLI Release 构建合同 7 / 24，概览归档合同 3 / 26，`verify_release_contract.rb` 对 App/CLI/Xcode 版本 `2.12.0-rc1747`、build `1747` 验证通过；`git diff --check` 通过。
- 本版只增加跨模块回归，不修改生产编辑代码。测试调用产品模型与项目数据 API，不等同于真实鼠标拖动/窗口 GUI 冒烟；没有运行四十版本全量构建、安装或第三方 Photoshop 验收。下一门槛仍为 rc1760。
